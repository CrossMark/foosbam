# Contributing to Foosbam

Contributions are welcome, as long as they follow the [PolyForm Noncommercial License](LICENSE).

## Issues

Use GitHub Issues to report bugs, suggest improvements, or describe questions. Include enough context to reproduce a problem where possible:

- what you were trying to do;
- what you expected to happen;
- what happened instead;
- relevant error messages and steps to reproduce.

## Picking up an issue

You are welcome to work on an open issue. First leave a comment saying that you would like to work on it, then ask for the issue to be formally assigned to you. The assignment is the source of truth for issue ownership and helps prevent duplicated work. Do your best to keep the change focused and explain any decisions in the pull request.

## Pull requests

1. Create a branch for your change.
2. Make the smallest focused change that addresses the issue.
3. Update documentation when behavior or setup changes.
4. Create and review a database migration when changing SQLAlchemy models.
5. Test the affected workflow locally.
6. Open a pull request describing the change and how it was tested.

There is no expectation that every contribution is perfect. Clear context, honest notes about limitations, and a good-faith effort to test the change are more useful than polished presentation.

## Licensing contributions

By submitting a contribution, you agree that it may be distributed as part of Foosbam under the [PolyForm Noncommercial License 1.0.0](LICENSE). Please do not submit code or content that you do not have permission to contribute.
